# journal-tracker

Два независимых продукта в одном репозитории:

- **`index.html`** — личный трекер-журнал (PWA, задачи/идеи/заметки, встроенный Claude-агент). Плюс `sw.js`, `manifest.json`, `icon.svg`.
- **`teleprompter.html`** — автономный телесуфлёр для записи видео в блог (Инстаграм). Один самодостаточный файл, ни от чего не зависит. Не связывать его с трекером — владелец просил держать их раздельно.

Сайт публикуется на GitHub Pages **автоматически при каждом пуше в `main`** (workflow `.github/workflows/pages.yml`, публикация занимает ~минуту):

- Суфлёр (личная версия владельца, его закладка): https://aleksandr1304.github.io/journal-tracker/teleprompter.html
- Суфлёр (публичная, короткий адрес для раздачи): https://aleksandr1304.github.io/ — собирается отдельным репозиторием `Aleksandr1304.github.io` (ежедневно и при пуше туда) из teleprompter.html с вырезанными PERSONAL-метками
- Суфлёр (публичная, старый адрес, тоже живой): https://aleksandr1304.github.io/journal-tracker/prompter.html

`prompter.html` **генерируется на публикации** из `teleprompter.html` (сейчас они функционально идентичны — тексты передаются ссылками и на страницах ничего личного нет). В git `prompter.html` не кладётся (есть в `.gitignore`). Правки функций суфлёра делай в `teleprompter.html`; если когда-нибудь появится что-то личное для владельца — оберни метками `<!-- PERSONAL:START/END -->` (HTML) или `/* PERSONAL:START/END */` (JS), workflow вырежет это из публичной версии.

## Суфлёр: как отправить текст («отправь текст в суфлёр»)

Личная страница владельца (его закладка) — `/journal-tracker/teleprompter.html`. Она сама
подтягивает текст из **ветки `script-drop`** (сырой файл `script.json` через raw.githubusercontent).
Владелец просто открывает закладку — текст уже стоит. Публичные версии собираются с вырезанными
метками PERSONAL и этот канал не видят вовсе.

Отправка текста — plumbing-пуш одиночного коммита без родителей (мгновенно, без PR,
без следов в истории main; владелец одобрил пуш в ветку `script-drop`):

```bash
cd <клон journal-tracker>
cat > /tmp/script.json <<'JSON'
{ "title": "Название ролика", "text": "Полный текст. Переводы строк — \n, абзацы — \n\n.", "updatedAt": "<теперь, ISO 8601 UTC>" }
JSON
python3 -c "import json; json.load(open('/tmp/script.json'))"   # проверить валидность!
BLOB=$(git hash-object -w /tmp/script.json)
TREE=$(printf '100644 blob %s\tscript.json\n' "$BLOB" | git mktree)
COMMIT=$(git commit-tree "$TREE" -m "текст суфлёра")
git push -f origin "$COMMIT:refs/heads/script-drop"
```

- `updatedAt` обязан отличаться от прежнего — по нему страница видит новый текст.
- Текст пиши как для чтения вслух: короткие фразы, без markdown, абзацы через пустую строку.
- Доставка мгновенная (без пересборки сайта): владелец открывает закладку или жмёт
  «⟳ Проверить новый текст».
- **Автоочистка**: workflow `clear-script.yml` каждые 6 часов стирает текст старше 6 часов
  (локальная копия у владельца в localStorage остаётся). Нужно снова — просто запушь ещё раз.
- Ветка `script-drop` всегда состоит из одного коммита без истории; в историю `main` тексты
  не попадают (старые, до 2026-08-11, там остались — новые нет).

Запасной канал (для передачи текста НЕ владельцу или без пуша): ссылка с текстом во фрагменте
`…/teleprompter.html#title=<encodeURIComponent(...)>&text=<encodeURIComponent(...)>` — фрагмент
не уходит даже на сервер.

**Ограничения прав Claude-интеграции в этом репозитории:** нет `workflow_dispatch`
(`actions_run_trigger` → 403) и нет создания репозиториев. Не пытаться — использовать пуши.

## Суфлёр: записанные видео в Telegram

После записи владелец отправляет ролик кнопкой «Отправить в Telegram» своему личному боту
(токен и chat id хранятся только в localStorage его устройства). Когда владелец просит
«проверь ролики / забери видео из бота»:

- Токен бота ищи в переменной окружения `TELEGRAM_BOT_TOKEN` (владелец добавляет её в
  настройках окружения Claude Code). **Токен никогда не коммитить и не печатать в логах/чате.**
- `POST https://api.telegram.org/bot<TOKEN>/getUpdates` — список сообщений; у видео смотри
  `message.video` (caption, duration, file_size, date, file_id).
- Файл можно скачать через `getFile` + `https://api.telegram.org/file/bot<TOKEN>/<file_path>` —
  но только до 20 МБ (лимит Telegram для ботов). Ролики крупнее — работать по метаданным.
- Скачанные видео в git не класть.
- Если api.telegram.org недоступен из песочницы — это сетевая политика окружения; попроси
  владельца разрешить домен в настройках окружения, сам ничего не обходи.

## Правки кода

Изменения кода (не `script.json`) — через ветку и PR, как обычно. Файлы трекера (`index.html`, `sw.js`, `manifest.json`) не трогать при работе над суфлёром.
